# 图标投稿、审核和发布

- `icon-submit.html` 提交到 `liangyou-icon-review.maddestalistar.workers.dev`。
- 投稿图片和元数据保存在 `MaddestAlistar/Icon-Review-Queue/pending/`。
- `icon-review-admin.html` 使用仅留在本次页面内存中的管理员密钥审核。
- 点击通过后，Worker 校验两份正式订阅，并在 `MaddestAlistar/LiangYou-IconLibrary` 的 **同一个 Git 提交**中写入图片、两份 JSON 和投稿发布凭据。
- 只有正式提交成功且两份订阅重新读取验证通过，才保存已通过状态。网络中断或审核元数据保存失败时，再次通过会读取同一投稿的发布凭据，核对已有图片和索引，不重复入库。
- 旧版已通过记录使用其 `publishedUrl` 核对正式图片和两份索引。没有足够发布证据的旧记录不会自动重复上传。
- 多人同时发布产生分支冲突时，重新读取最新索引并重试，禁止强制覆盖。
- 已发布图标使用独立「下架」按钮，确认后按正式图片 URL 精确移除两份订阅中的记录，同时写入下架凭据，最后保存已下架状态。原图片保留，便于追溯；同名但不同 URL 的图标不受影响，前五个置顶图标受保护。
- 下架失败可重试；正式库已经移除、审核状态尚未保存时，再点下架会核对已有结果。下架凭据会阻止旧页面误点通过而重新入库。「已下架」筛选和「核对下架」可复核结果。
- 下架仅影响订阅目录；客户端需刷新订阅，已下载或已应用的图标不会从用户设备上被远程删除。
- 置顶五个图标保留，其他名称按原规则排序，数字开头放末尾；动态名称包含“动态”和序号。文件名以投稿 ID 唯一标识。
- 后台分批读取审核队列，每批最多 30 条，避免单次请求读取大量记录触及 Worker 子请求限制。

## 部署与校验

Worker 的 `GITHUB_TOKEN` 仅授权审核仓库 Contents 读写；`PUBLISH_GITHUB_TOKEN` 仅授权正式图标库 Contents 读写。`ADMIN_KEY` 至少 24 字符。三者都只能作为 Cloudflare 加密 Secret，不能放入网页或仓库。

GitHub 的 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID` 供部署工作流使用。`workers/**` 变动会先执行 `node --test scripts/test_icon*.mjs`，通过后部署，再检查 `/health` 版本和未认证 `/admin` 返回 401。

回归测试覆盖：真实换行/中文编码、JSON 损坏阻断、图片和双索引原子发布、失败不泄露半成品、并发编辑、重试不重复、旧记录核对、大型 JSON 的 Contents API 回退。

正式图标库另有 `Validate icon subscriptions` 工作流，每次更新及每天检查 JSON 格式、本地图片存在性、置顶一致性和精选库包含于完整库。网页目录统计按原有定时任务同步；客户端需刷新订阅，CDN 缓存可能短暂延迟。

## GIF 预览与联系邮箱

- 投稿页按文件后缀自动选择类型。GIF 通过原始文件的 Blob URL 预览，默认自动播放，支持重新播放、停止并查看静态帧；系统开启减少动态效果时默认静态，用户可手动播放。播放次数跟随原文件，单帧 GIF 不会产生动画。预览不重编码上传文件。
- 联系邮箱选填，前后端校验格式与 254 字符上限；历史无邮箱记录正常显示「未填写」。后台提供「复制邮箱」，剪贴板权限不可用时提示手动复制；不会自动发邮件。
- 审核仓库为公开仓库，邮箱绝不以明文写入元数据、日志、提交信息或正式发布凭据。使用 Web Crypto HKDF + AES-256-GCM，随机 96 位 IV，以投稿 ID 为认证附加数据；只有认证后的后台响应解密邮箱，公开投稿响应不返回邮箱。邮箱不能解密时显示明确提示，不影响图标审核。
- 加密优先使用可选 Cloudflare Secret `CONTACT_EMAIL_KEY`（至少 24 字符，建议随机 32 字节以上）；未配置时使用已有 `ADMIN_KEY` 派生独立用途密钥，无需额外配置即可启用。密钥必须是高熵随机值。
- **轮换密钥前必须保留解密能力**：轮换 `ADMIN_KEY` 时将旧值保留为 Cloudflare Secret `CONTACT_EMAIL_PREVIOUS_ADMIN_KEY`；轮换专用密钥时将旧值保留为 `CONTACT_EMAIL_PREVIOUS_KEY`。下一次轮换前应先将旧邮箱记录迁移到当前密钥；否则更早记录将无法解密。不要把密钥写入仓库或日志。切换到专用密钥后仍能用原 ADMIN_KEY 解密既有记录。
- 投稿图片与元数据一直保留在 `Icon-Review-Queue/pending/`，批准、拒绝、下架都是修改同一元数据文件的 `status`，不移动、不删除图片，不自动恢复待审核。通过后台筛选「已拒绝」「已下架」「全部」查看；已拒绝的未发布记录可恢复待审核，已下架记录只支持核对下架。

## 批量投稿（ZIP / RAR / 多选图片）

- 投稿页提供单张与批量两种入口，共用作者、选填邮箱和说明。ZIP、RAR 在浏览器专用 Web Worker 内解包，45 秒超时可终止；不将整个压缩包上传到服务器。解析器和 WASM 自托管，不依赖第三方 CDN。
- 每次选择一个压缩包（最多 20 MB），或直接多选图片；每批最多 30 张、解压总量最多 50 MB、最多 500 个目录条目，单图仍限 10 MB。支持子文件夹，跳过隐藏文件、非图片、不安全路径和嵌套包；密码包、分卷包需用户先处理。
- 前端与 Worker 共享 `icon-image.mjs` 的文件签名和尺寸检查，前端额外执行浏览器图片解码；合格项默认勾选，错误项单独展示原因。同一批次内容相同的图片去重，名称可编辑，GIF 默认静态预览，可单独播放。
- 批量逐张提交；每张独立 UUID、同一批次共享 batchId。每项通过 Git Data API 在同一非强制提交中写入原图和加密邮箱元数据，然后更新队列分支。冲突重新读取最新分支，不覆盖其他审核或投稿。丢失响应后以同一 UUID 重试会核对内容，返回已有编号，不重复创建；不同内容复用 UUID 会拒绝。
- 本页内保留重试标识和首次发送资料；提交开始后资料锁定。停止按钮完成当前项后停止后续上传，失败时自动暂停，用户可继续。成功项不会再次上传。刷新或关闭页面后批次标识不会持久保存；请完成或重试当前批次后再离开。
- 后台逐张展示、审核、复制邮箱；显示批次 ID，搜索支持批次 ID。通过 / 拒绝 / 下架仍为单项操作，不会批准整个压缩包。审核目录达到 Contents API 的 1,000 条目上限后改用目录 Git Tree 列表，避免批量增加记录后静默漏项。
- 本仓库中 `scripts/fixtures/icon-batch/` 是本地生成的合格静态、合格动态、错误尺寸和文本文件的 ZIP / RAR 测试包；测试使用 mock GitHub，不创建真实投稿。
